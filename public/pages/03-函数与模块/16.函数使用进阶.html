16.函数使用进阶

函数使用进阶

前面我们学会了定义函数、给函数传参数、拿函数的返回值，也学会了用模块把函数组织起来。这一讲我们学习三种更"高级"的函数用法：Lambda 函数、递归调用和生成器。前一种是写小函数的捷径，后两种写法看起来和普通的循环不太一样，但它们是 Python 中非常常见、也非常实用的工具。

Lambda函数

前面我们用def定义函数时，函数体至少要写一行代码。但很多时候我们需要的规则非常简单，比如"加 10""求平方""判断是不是偶数"，写一个完整的函数显得有点啰嗦，这时我们就可以使用Lambda 函数。

Python 中的 lambda 函数是没有名字的函数，所以很多人也把它叫做匿名函数。lambda 函数只能有一行代码，代码中的表达式产生的运算结果就是这个匿名函数的返回值，代码如下所示。

python
# 加 10
add10 = lambda x: x + 10
# 求平方
square = lambda x: x ** 2
# 判断是不是偶数
is_even = lambda x: x % 2 == 0


print(add10(5))    # 15
print(square(5))   # 25
print(is_even(5))  # False

定义 lambda 函数的关键字是lambda，后面跟函数的参数，如果有多个参数用逗号进行分隔；冒号后面的部分就是函数的执行体，通常是一个表达式，表达式的运算结果就是 lambda 函数的返回值，不需要写return关键字。

lambda最常见的用法：给排序指定规则

我们在《14.函数和模块》一讲中讲过sorted函数，它默认按元素本身排序。如果列表中装的是元组，排序就会先比较元组的第一个元素，这时候就需要给sorted函数传一个key参数，告诉它"按什么来排"。

key参数要的是一个函数，而 lambda 函数正好可以在一行之内把这个函数写出来，代码如下所示。

python
students = [('张三', 95), ('李四', 82), ('王五', 67), ('赵六', 45)]

# 按成绩从高到低排序
ranked = sorted(students, key=lambda item: item[1], reverse=True)
print(ranked)

输出：

text
[('张三', 95), ('李四', 82), ('王五', 67), ('赵六', 45)]

上面代码中key=lambda item: item[1]的意思是：排序的时候，对每个元素先用 lambda 函数算出它的"排序依据"——这里取的是元组的第二个元素（也就是成绩），然后按这个依据排序；reverse=True表示从大到小排。如果把reverse=True去掉，得到的就是从低到高排列。

需要提醒大家的是，lambda 函数虽然写起来短，但可读性不如def定义的具名函数。所以在实际开发中请遵循下面的原则：

  • 规则复杂、需要复用、需要加注释说明的，一律用def定义具名函数；
  • 规则只有一行、只用一次、意思一目了然的，才考虑使用 lambda 函数；
  • 团队代码中优先保证"看得懂"，而不是"写得短"。

递归调用

Python 中允许函数之间相互调用，而且一个函数还可以直接或者间接地调用自身。函数自己调用自己，就称为递归调用。

递归其实并不神秘，我们来看一个生活中的例子：要计算 $n$ 个数的总和，可以把 $n$ 拆成"$n-1$ 个数的总和"加上最后一个数；那么"$n-1$ 个数的总和"又可以继续这样拆下去……一直拆到只剩一个数为止。这正是递归的思路。

很多数学问题的定义本身就是递归定义的，例如我们之前讲到的阶乘，非负整数N的阶乘是N乘以N-1的阶乘，即 $\small{N! = N \times (N-1)!}$ ，定义的左边和右边都出现了阶乘的概念，所以这是一个递归定义。既然如此，我们可以使用递归调用的方式来写一个求阶乘的函数，代码如下所示。

python
def fac(num):
    """求阶乘"""
    if num in (0, 1):
        return 1
    return num * fac(num - 1)

上面的代码中，fac函数中又调用了fac函数，这就是所谓的递归调用。代码第3行的if条件叫做递归的收敛条件，简单的说就是"什么时候要结束函数的递归调用"，在计算阶乘时，如果计算到0或1的阶乘，就停止递归调用，直接返回1；代码第4行的num * fac(num - 1)是递归公式，也就是阶乘的递归定义。

下面，我们简单的分析下，如果用fac(5)计算5的阶乘，整个过程会是怎样的。

python
# 递归调用函数入栈
# 5 * fac(4)
# 5 * (4 * fac(3))
# 5 * (4 * (3 * fac(2)))
# 5 * (4 * (3 * (2 * fac(1))))
# 停止递归函数出栈
# 5 * (4 * (3 * (2 * 1)))
# 5 * (4 * (3 * 2))
# 5 * (4 * 6)
# 5 * 24
# 120
print(fac(5))    # 120

从上面的过程可以看出，递归其实是"先一路拆到底，再一路算回来"。写递归函数时，只要抓住下面两个要点，就不会写错。

  • 递归出口：什么条件下停止调用自己；
  • 递归公式：如何把当前问题变成规模更小的同类问题。

再说说递归用到的"栈"。函数调用会通过内存中称为"栈"（stack）的数据结构来保存当前代码的执行现场，函数调用结束后会通过这个栈结构恢复之前的执行现场。栈是一种先进后出的数据结构，这也就意味着最早入栈的函数最后才能返回，而最后入栈的函数会最先返回。

我们可以用"叠盘子"来理解这个过程：每调用一个函数，就相当于在桌子上叠上一个盘子（这个盘子用来保存"我算到哪一步了"）；函数执行结束返回时，再把盘子取走。盘子叠得越高，占用的空间就越多。通常，内存中的栈空间很小，因此递归调用的次数如果太多，会导致栈溢出（stack overflow），所以递归调用一定要确保能够快速收敛。

我们可以尝试执行fac(5000)，看看是不是会提示RecursionError错误，错误消息为：maximum recursion depth exceeded in comparison（超出最大递归深度），其实就是发生了栈溢出。

如果我们使用官方的 Python 解释器（CPython），默认将函数调用的栈结构最大深度设置为1000层。如果超出这个深度，就会发生上面说的RecursionError。当然，我们可以使用sys模块的setrecursionlimit函数来改变递归调用的最大深度，但是我们不建议这样做，因为让递归快速收敛才是我们应该做的事情，否则就应该考虑使用循环递推而不是递归。

再举一个之前讲过的生成斐波那契数列的例子，因为斐波那契数列前两个数都是1，从第三个数开始，每个数是前两个数相加的和，可以记为f(n) = f(n - 1) + f(n - 2)，很显然这又是一个递归的定义，所以我们可以用下面的递归调用函数来计算第n个斐波那契数。

python
def fib1(n):
    """递归计算第n个斐波那契数"""
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 11):
    print(fib1(i))

需要提醒大家，上面计算斐波那契数的代码虽然看起来非常简单明了，但执行性能是比较糟糕的。大家可以试一试，把上面代码for循环中range函数的第二个参数修改为31，即输出前30个斐波那契数，看看需要多长时间；也欢迎大家在评论区留下你的代码执行时间。至于为什么这么慢，大家可以自己思考一下原因。

很显然，直接使用循环递推的方式获得斐波那契数列是更好的选择，代码如下所示。

python
def fib2(n):
    """循环计算第n个斐波那契数"""
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

比较上面两种写法，我们可以得到一个朴素的结论：能用循环写清楚的题目，就不要用递归。递归真正的价值在于，那些"问题本身就是递归定义"的场景，比如文件夹的层层查找、树的遍历、分形图形等。当然，递归也是学习生成器（下一节内容）的重要基础。

生成器

我们前面学过的列表有一个特点：要把里面的所有元素一次性都放进内存里。如果数据量非常大（比如一百万个数字），这就会占用相当可观的内存。

有没有办法"要一个算一个，用完一个扔一个"呢？这就是生成器（generator）的本领。

生成器函数

我们先来看一个生成器函数的例子，代码如下所示。

python
def counter(n):
    """依次产出 1 到 n 的整数"""
    i = 1
    while i <= n:
        yield i
        i += 1

这个函数和普通函数只有一个关键区别：函数体里出现了yield关键字。只要函数体中出现yield，这个函数就变成了生成器函数，调用它得到的也不是普通函数返回值，而是一个生成器对象。

yield的作用可以这样理解：**函数执行到yield这一行就"停住"，把yield后面表达式的值交出去；等调用者要下一个值时，再从停住的地方接着往下执行。**这跟return不一样——return一执行函数就结束了，而yield执行完函数还留着"下半截"没跑。

我们可以用for循环来遍历生成器，代码如下所示。

python
def counter(n):
    """依次产出 1 到 n 的整数"""
    i = 1
    while i <= n:
        yield i
        i += 1


gen = counter(5)
for value in gen:
    print(value)

输出：

text
1
2
3
4
5

注意观察上面代码的执行过程：counter(5)被调用时，函数体一行都还没有执行（生成器函数是"懒"的）；只有在for循环开始取第一个值时，函数才真正开始运行，跑到yield i把1交出来；交出1之后函数停在那里，直到for循环要下一个值，它才从停住的地方继续，把i加一后交出2，如此往复，直到i超过n，函数结束。

如果想一次只取一个值，可以使用内置函数next，代码如下所示。

python
def counter(n):
    """依次产出 1 到 n 的整数"""
    i = 1
    while i <= n:
        yield i
        i += 1


gen = counter(3)
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3
# 生成器里的数已经取完了，再取就会引发StopIteration异常

生成器表达式

除了生成器函数，Python 还提供了更简洁的生成器表达式——就是把列表生成式的方括号换成圆括号，代码如下所示。

python
gen = (num ** 2 for num in range(5))
print(list(gen))  # [0, 1, 4, 9, 16]

提示：本节内容也可以课后自学，课上时间紧张时可以略过。生成器表达式就是把列表生成式的方括号换成圆括号，学生自己一看就能明白。

对比一下这两种写法：

python
# 列表生成式：一次性把 5 个结果全部算出来，放进列表
squares = [num ** 2 for num in range(5)]

# 生成器表达式：要一个算一个，用完一个扔一个
squares = (num ** 2 for num in range(5))

当数据量小的时候，两者的结果完全一样；数据量很大的时候，区别就非常明显了。

python
# 列表生成式：先把一百万个结果全部算出来放进内存
squares = [num ** 2 for num in range(1000000)]

# 生成器表达式：随用随算，内存占用几乎和数据量无关
squares = (num ** 2 for num in range(1000000))

生成器的典型用途

生成器最常见的用途是"处理数量不确定或体量很大的数据"，下面这个例子用生成器产出斐波那契数列，它和前面递归版本得到的是同样的结果，但不会重复计算，执行速度要快得多。

python
def fib_gen(n):
    """生成前 n 个斐波那契数"""
    a, b = 0, 1
    for _ in range(n):
        yield a
        a, b = b, a + b


for num in fib_gen(10):
    print(num)

除了生成数据，生成器还经常用在读取大文件的场景——后面我们学习文件读写时会再次遇到它：文件有多少行就读多少行，一次只占用一小块内存，而不是把整个文件都塞进内存。

知识点总结

本讲学习了三种"函数的高级用法"：Lambda 函数用来快速定义一行的小规则，递归解决"问题本身是递归定义"的场景，生成器解决"数据量大、不需要一次性全部拿到"的场景。

  • 概念：Lambda 函数（lambda）是没有名字的函数，只能写一行，表达式结果就是返回值，也叫匿名函数；递归调用指函数直接或间接调用自身；生成器是包含yield语句的函数所返回的对象，它可以"一次产出一个值"，用完即弃。生成器表达式是列表生成式的"惰性"版本，把方括号换成圆括号即可。
  • 操作方法：lambda 的语法是lambda 参数: 表达式，不需要写return；给sorted函数传key=lambda ...可以自定义排序规则；递归函数必须写清递归出口和递归公式；遍历生成器用for循环，取单个值用next()，取完会引发StopIteration异常。
  • 代码要点：key=lambda item: item[1]表示"取元组的第二个元素作为排序依据"，reverse=True表示从大到小排；fac函数的出口是num in (0, 1)；fib_gen用yield a逐个产出斐波那契数；yield只暂停函数而不会结束它，这一点和return完全不同。
  • 命名规则：lambda 函数虽然匿名，但绑定给变量后（add10、square）仍应见名知意；生成器函数建议用动宾结构体现产出什么（如counter、fib_gen）；yield后面的变量名要能表达"这个值是什么"。
  • 注意事项：能用循环写清楚就不要用递归；递归必须能快速收敛，否则会触发RecursionError（默认最大深度 1000 层），不建议用setrecursionlimit硬撑；生成器只能遍历一次，遍历完需要重新创建；lambda 只适合一行就能说清的简单规则，复杂逻辑仍然应该用def定义具名函数；把函数作为参数、高阶函数、偏函数、装饰器属于提高内容，课堂不要求掌握，请课后阅读《函数高级应用》。
  • 学习重点：能写出一行简单的 lambda 函数并说清楚它的参数和返回值；能独立写出一个带递归出口的递归函数，并说清楚它是怎么一层层拆解问题的；理解生成器"要一个算一个"的特点，能把一段列表生成式改写成生成器表达式，并知道这样做能节省内存。
